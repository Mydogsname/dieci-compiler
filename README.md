# dieci-compiler（叠词）

生成有注释的提示词：源正文先被拆成「一句一行」的语义文件，多份语义文件再被叠成「词 → 原句（来源）」的配对。

## 它解决什么
ai遗忘，记错，控制ai的行为

## 安装

```sh
pnpm dsh plugin --profile <profile> add dieci-compiler
pnpm dsh --profile <profile> --dump-config   # 输出里应有 "# == dieci-compiler"
```

从目录装（开发时）：

```sh
pnpm dsh plugin --profile <profile> add ./dieci-compiler
```

卸载：

```sh
pnpm dsh plugin --profile <profile> remove dieci-compiler
```

## 装完有什么

**五个工具**

| 工具 | 读写 | 作用 |
|---|---|---|
| `decompose` | 写 `语义/` | 正文 → 语义文件；自检通过才落盘，否则重试（最多 3 次）后报错不写 |
| `check_notes` | **只读** | 语义文件 ↔ 源文件对账：一句一行、保真、覆盖、组间空行 |
| `dieci` | 只读（可选落盘） | **无题提取**：多份语义文件 → 词与句的跨文件配对，写出「注释表」与「剩余文本」 |
| `supplement` | 写注释表与剩余文本 | **有题提取**：剩余文本 + 题目 → 一张主题注释表；取走的句子从剩余文本删掉 |
| `compose` | 只读（可选落盘） | 注释表（一份或多份）+ 剩余文本 → 成稿：首行「主题：」，正文只用这两块原料里的事实与用词 |

> `dieci` 与 `supplement` 都只做注释；成品一律由 `compose` 出。

注释表命名分来源，`compose` 按这个顺序叠层：

- `dieci`（无题提取，管内容）：`叠词\<工作区名>-注释.txt`
- `supplement`（有题提取，补规格与约束）：`叠词\<题目>-主题-注释.txt`

**三条命令**

| 命令 | 参数 | 作用 |
|---|---|---|
| `/dieci` | 无 | 无题提取：处理工作区全部 `.md`/`.txt`，逐份自检 → 缺/不合格的补 `decompose` 并复核 → 全部通过后 `dieci`。产物：`<工作区>\叠词\<工作区名>-注释.txt`、`<工作区>\<工作区名>-剩余.txt`。**不出成品** |
| `/supplement` | 题目（必填） | 有题提取：把这句话当题目，从剩余文本取句写成 `叠词\<题目>-主题-注释.txt`，削薄剩余文本，追加提取记录。只做一步，不出成品 |
| `/compose` | 无 | 叠 `叠词\` 下全部注释表 + `<工作区名>-剩余.txt` → `叠词\<工作区名>.txt`（重跑覆盖）。注释表为空时报明该先跑哪条命令 |

要指定注释表的层次或换落点，就别用命令，直接调 `compose` 工具（`notes` 数组 + `out`）。

命令名受宿主约束：`^[a-z][a-z0-9_-]*$`，中文名不可用。

**一段系统提示** —— 每个会话默认就懂叠词工作流（`tool:dieci`，order 116）。

> `/save` 仍未实现。

## 工作流

```
正文.md ──decompose──> 语义/正文-语义.txt ──┐
正文2.md ─decompose──> 语义/正文2-语义.txt ─┴─dieci──> 叠词\<工作区名>-注释.txt + <工作区名>-剩余.txt
                                └──check_notes──> 通过 / 未通过

剩余文本 + 题目 ──supplement──> 叠词\<题目>-主题-注释.txt（取走的句子从剩余文本删掉）
叠词\ 全部注释表 + 剩余文本 ──compose──> 叠词\<工作区名>.txt
```

三条命令各管一步：`/dieci`（无题提取）、`/supplement <题目>`（有题提取）、`/compose`（出成品）。

`dieci` 在读素材前会先用同一份判据复核语义文件，不合格直接拒，不自动重新划分。

**无题提取 vs 有题提取**：`dieci` 没有题目，只按「同指」把跨文件的句子并到一个词下；`supplement` 有题目，按「同题」从剩余文本里取句成词。两者都只做注释，成品归 `compose`。

**剩余文本 = 语义集合减去被收走的部分**，所以它只减不增：`supplement` 每取走一批就删掉，取空是正常终点。每次提取在根目录 `提取记录.txt` 追加一行：

```
2026-10-26 11:28	dieci	题目：工作区	生成 13 句剩余文本
2026-10-26 15:02	supplement	题目：画面禁忌与版式	取走 2 句	剩余 3 句
```

`/dieci` 把上面这条链固化：`check_notes` 当闸门，缺/不合格才补 `decompose`，复核通过后进 `dieci`，任一步失败即中止并回前序步骤。素材取自工作区（递归，跳过 `语义\`、`叠词\`、`node_modules`、`.git` 等目录），上限 30 份。

**产物名取工作区目录名**（会话头 `SessionHeader` 只有 `cwd`，没有工作区标题，所以名字只能从 `cwd` 的目录名来；空则回落字面量「工作区」）：

```
工作区目录 testwork ⇒
<工作区>\叠词\testwork-注释.txt        ← dieci 的注释表
<工作区>\叠词\<题目>-主题-注释.txt      ← supplement 的主题注释表（可多份）
<工作区>\testwork-剩余.txt             ← 剩余文本，全局一份
<工作区>\叠词\testwork.txt             ← 成品（/compose，重跑覆盖）
<工作区>\提取记录.txt                  ← 每次提取一行
```

主题是 `compose` 的副产品，命令不预支，所以反复运行不会产生新文件。成品由 `compose` 写到你给的 `out`。

**下一轮不重吃产物**：`叠词\` 在 `SKIP_DIRS` 里，注释表天然被跳过；剩余文本与提取记录靠 `GENERATED` 的名字规则排除。所以重跑 `/dieci` 时素材仍是原来那几份。

`compose` 读哪些注释表：缺省扫 `叠词\` 下全部，**先 `-注释.txt`（管内容）、后 `-主题-注释.txt`（补规格与约束）**；也可用 `notes` 显式给数组定顺序。剩余文本缺省 `<工作区>\<工作区名>-剩余.txt`。

## 文件格式

语义文件（`语义/<主名>-语义.txt`）：

```
她叫沈青梧，二十七岁，在城南一家旧书店做店员。      ← 一句一行，原文一字不动
身高一米六五，偏瘦，肩膀窄，习惯微微含胸。
                                                     ← 空行 = 组界，恰好一行
脸型偏鹅蛋，下颌线条柔和，颧骨不高，皮肤偏冷白。
```

自检四条：

1. **一句一行**：每个非空行正好是源文按 `。！？；` 切出的一句，行序与正文一致
2. **保真**：行内文字与对应源句逐字相同（只忽略空白差异）
3. **覆盖**：源文每句都入语义文件，不多不少、不重复
4. **结构**：组与组之间恰好一个空行

注释表格式（`dieci` 与 `supplement` 的产出，二者同构）：`词：原句`，同词多句时续行两空格缩进。

```
旧书店：她叫沈青梧，二十七岁，在城南一家旧书店做店员。
  背景是旧书店内部，木质书架，暖黄灯光。
```

剩余文本格式：一行一句，行首 `（来源文件）`，原样不改。它只减不增——被 `supplement` 取走的行直接删掉。

```
（生成场景图.md）不要人物，不要现代元素。
（人物描写.md）身高一米六五，偏瘦，肩膀窄，习惯微微含胸。
```

## 源码结构

```
src/
├─ index.js        入口：注册五个工具 + 可选挂 /dieci 与系统提示段
├─ guide.js        系统提示段正文
├─ core/text.js    判据本体：切句 / 解析 / 比对 / 路径（无 fs、无模型）
├─ core/record.js  提取记录：时间 / 工具 / 题目 / 取走或生成几句
├─ tools/          decompose.js · check_notes.js · dieci.js · supplement.js · compose.js
└─ commands/       dieci.js（/dieci）· supplement.js（/supplement）
```

## 配置

本包暂无可配字段。`maxTokens` 跟随会话路由（缺省 8192）；decompose 与 dieci 都以 `temperature 0` 调用模型，减少同一素材每次划分不一致。
