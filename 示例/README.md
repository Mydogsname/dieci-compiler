# 示例

一份最小工作区：只有两份源文，没有别的。

```
示例/
├─ 黑色的扩散.txt    散文，30 句
└─ 生图要点.txt      提示词格式说明，10 句
```

想看产物长什么样，读下面就行，不用真跑。想复现，把这两份文件拷到一个空目录，在那个目录开会话，跑 `/dieci` 再 `/compose 黑色金鱼生图提示词`。

> 真要在这个目录里直接跑，先把本文件（`README.md`）移走——`/dieci` 会把工作区里所有 `.md`/`.txt` 当素材扫走。

## 第一步：`/dieci`

扫到两份源文，各拆一份语义文件，再跨文件配对。得到：

```
<工作区>/
├─ 语义/黑色的扩散-语义.txt
├─ 语义/生图要点-语义.txt
├─ 叠词/示例-注释.txt          ← 工作区目录名是 示例
├─ 示例-剩余.txt
└─ 提取记录.txt
```

`叠词/示例-注释.txt` 长这样（节选）——一个词一行，同词的句子两空格缩进：

```
金鱼：然后我看见了那条金鱼。
  它就在浅水处，黑色的，鳞片在某种不知来源的光线下泛着油润的光泽。
  体型正常，姿态正常，游动时带着那种金鱼特有的、略显笨拙的摆动。

鱼尾：但当我再看了一眼它的尾巴——
  像一团被风吹乱的墨，像冬天呵出的白雾，像焚烧后升腾的黑烟。
  黑色的纹路在河面上蜿蜒爬行，和鱼尾之间连着千丝万缕的细线，像血管，像蛛网。
```

没被任何词收走的句子进 `示例-剩余.txt`（节选）：

```
（黑色的扩散.txt）我甚至觉得它有些可爱，像谁从鱼缸里随手丢出来的一条。
（生图要点.txt）负面提示用来排除模糊、畸形、水印等不希望出现的内容；
```

## 第二步：`/compose 黑色金鱼生图提示词`

叠 `叠词/` 下所有注释表 + 剩余文本，出成品 `叠词/示例-黑色金鱼生图提示词.txt`。一共十行，段与段紧挨着，不空行：

```
主题：黑色金鱼生图提示词

主体：一条黑色金鱼，体型正常，姿态正常，游动时带着金鱼特有的、略显笨拙的摆动；鳞片在某种不知来源的光线下泛着油润的光泽；尾鳍本来应该是一层薄薄的透明膜，但尾巴在无限地分叉、延展、弥散……
场景：河面，河水很静，静得像一面被遗忘的镜子；岸上脚底是碎石和干裂的泥土；顺着河面，像有人往清水里滴了一滴浓墨，河面黑了；……
风格媒介：摄影。
构图镜头：金鱼悬在黑色正中央，黑色纹路在河面上蜿蜒爬行，和鱼尾之间连着千丝万缕的细线，像血管，像蛛网；……
```

产物形态由主题决定：写「生图提示词」就出提示词，写「一段散文」就出散文。

## 可选：多一层规格

想让成品带上更硬的约束（比例、禁止项），先跑一次 `/supplement`：

```
/supplement 负面约束
```

它从剩余文本里挑出属于这个题目的句子，单独写一张 `叠词/负面约束-注释.txt`。之后 `/compose` 会把它和其它注释表一起叠——`<工作区名>-注释.txt` 管内容，其余按文件名排在后面补规格。

## 这份示例会错在哪

- **归词会错**。示例里 `光线`、`色彩`、`场景` 三个词，各混进了一条提示词格式说明句（「光线氛围说明光源方向…」这类）；`鱼尾` 名下收的其实是讲「扩散」的比喻，真正描述尾鳍的那句反倒落在 `金鱼` 下。出成品前扫一眼注释表。
- **只认中文标点**。切句按 `。！？；`，英文稿或代码会被整段当成一句，而且自检会判「通过」。
- 重跑 `/dieci` 是重新生成，不是增量：`示例-剩余.txt` 会被整体重写，之前 `/supplement` 取走的句子会回来，而它那张主题注释表还在——同一句就两处都有了。
